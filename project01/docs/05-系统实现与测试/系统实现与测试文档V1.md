## 1. 系统概述

Nebula Studio（文图互转主题设计系统）是一个前后端分离的全栈 Web 应用，提供文本生成图像（Text-to-Image）与图像生成文本（Image-to-Text）的双向转换功能，支持多种 AI 服务提供商，并具备用户管理、风格管理、LoRA 模型训练、管理后台等完整业务能力。

### 核心功能

| 功能模块 | 描述 |
|----------|------|
| 文生图 | 输入文本提示词，通过 AI 模型生成图像 |
| 图生文 | 上传图像，通过 AI 模型生成文本描述 |
| 风格管理 | 管理设计主题风格，配置提示词模板 |
| LoRA 训练 | 管理 LoRA 模型训练任务 |
| 用户管理 | 注册、登录、权限控制（USER / DESIGNER / ADMIN） |
| 管理后台 | 系统配置、审计日志、模型管理、用户管理、仪表盘 |

### 技术栈总览

| 层级 | 技术 | 版本 |
|------|------|------|
| 前端框架 | Vue 3 (Composition API) | ^3.4.21 |
| 构建工具 | Vite | ^5.2.0 |
| UI 组件库 | Element Plus | ^2.7.0 |
| 状态管理 | Pinia | ^2.1.7 |
| 路由 | Vue Router | ^4.3.0 |
| HTTP 客户端 | Axios | ^1.6.8 |
| 后端框架 | Spring Boot | 3.2.5 |
| Java 版本 | JDK | 17 |
| ORM | MyBatis-Plus | 3.5.6 |
| 安全 | Spring Security + JWT（jjwt 0.12.5） | — |
| 数据库 | H2（开发）/ MySQL（生产） | — |
| 构建工具 | Maven | — |
| Python CLI | Python + requests + pytest | >=3.14 |

后端采用 Spring Boot 3 分层架构：

```
Controller 层 → Service 接口层 → Service Impl 层 → Mapper 层 → Database
                                      ↕
                              AI Provider 策略层
                               (Text2ImageProvider /
                                Image2TextProvider)
```

**主要设计模式：**

| 模式 | 用途 | 实现位置 |
|------|------|----------|
| 策略模式 | 多 AI 供应商切换与回退 | `ai/provider/*Provider.java` |

| AOP 切面 | 审计日志自动记录 | `aspect/AuditLogAspect.java` |
| 工厂模式 | Bean 自动注入与装配 | `config/AiServiceConfig.java` |

## 3. 系统实现

### 3.1 前端实现

#### 3.1.1 API 服务层

前端通过 `utils/request.js` 创建统一的 Axios 实例，配置了：

- **Base URL**：`http://localhost:8080/api`
- **请求拦截器**：自动附加 JWT Token（`Authorization: Bearer <token>`）
- **响应拦截器**：401 时自动跳转登录页，统一错误处理

API 服务模块按业务领域划分为 9 个文件：

```
api/
├── ai.js           # AI 状态查询/供应商切换
├── dashboard.js    # 仪表盘统计数据
├── image2text.js   # 图生文记录 CRUD
├── lora.js         # LoRA 训练任务管理
├── style.js        # 风格 CRUD
├── system.js       # 系统配置管理
├── text2image.js   # 文生图生成请求/记录
├── upload.js       # 文件上传（图片）
└── user.js         # 登录/注册/用户信息
```

#### 3.1.2 状态管理（Pinia）

**user store** — 管理用户认证状态：

```javascript
stores/user.js
├── state: token, userInfo, roles
├── actions: login, logout, fetchUserInfo
├── getters: isLoggedIn, isAdmin, isDesigner
```

**ai store** — 管理 AI 供应商状态：

```javascript
stores/ai.js
├── state: text2imageProviders, image2textProviders
├── actions: fetchStatus, switchProvider
```

#### 3.1.3 路由守卫

在 `router/index.js` 中实现三级权限控制：

- **全局前置守卫**：检查登录状态，未登录重定向到 `/login`
- **元数据权限标记**：路由配置中通过 `meta.roles` 声明所需角色
- **精细控制**：每个路由可设置 `USER`、`DESIGNER`、`ADMIN` 三种角色需求

#### 3.1.4 关键视图组件

| 视图 | 功能 |

| `Text2ImageView.vue` | 输入提示词 → 选择参数 → 调用 API → 展示生成图片；支持参数调节（steps, cfg, seed, 尺寸）和 AI 供应商切换 |

#### 3.4.1 策略模式架构

**双接口体系：**

```

└── generate(request)     → 生成图片

Image2TextProvider (interface)
├── getProviderName()      → 供应商标识
```

#### 3.4.2 AiProviderManager 提供商管理

核心管理组件，职责：

1. **自动注入**：Spring 自动收集所有 `Text2ImageProvider` 和 `Image2TextProvider` 实现
2. **激活管理**：通过 `application.yml` 配置或运行时 API 切换当前激活的提供商
3. **自动回退**：当激活的提供商不可用时，按优先级：激活 → 配置的回退 → mock
4. **状态查询**：提供所有注册提供商的状态列表

#### 3.4.3 ComfyUI 集成（核心实现）

**ComfyUIClient.java** — ComfyUI HTTP 协议封装：

```json
交互流程：
1. POST /prompt → { prompt: <workflow> } → 获取 prompt_id
2. GET  /history/{prompt_id} → 轮询（每2000ms，最长120s）→ 获取输出
3. GET  /view?filename=...&type=output → 下载图片字节流
```

**Workflow 节点映射（`comfyui_default.json`）：**

| 节点 ID | class_type | 用途 | 注入参数 |
|---------|-----------|------|----------|
| 26 | CLIPTextEncode | 正向提示词 | text |
| 22 | CLIPTextEncode | 负向提示词 | text |
| 24 | KSampler | 采样参数 | seed, steps, cfg, sampler_name |
| 25 | EmptyLatentImage | 图片尺寸 | width, height |
| 19 | VAEDecode | VAE 解码 | —（工作流固定） |
| 21 | CheckpointLoaderSimple | 模型加载 | —（工作流固定） |

**动态配置：**

- **API 地址**：通过 `system_config` 表键 `ai.comfyui.api-url` 运行时配置，优先于 `application.yml`
- **生效方式**：管理后台「系统配置 → ComfyUI API 地址」修改后即时生效，无需重启
- **兜底值**：`http://127.0.0.1:8188`

**ComfyUIText2ImageProvider.java** — 文生图生成流程：

1. 从 `Text2ImageRequest` 提取参数（prompt, negative_prompt, width, height, steps, cfg, seed, sampler_name）
2. 调用 `ComfyUIClient.loadWorkflow()` 加载工作流 JSON
3. 调用 `ComfyUIClient.injectParams(...)` 将参数注入对应节点
4. 调用 `ComfyUIClient.queuePrompt(...)` 提交生成任务
5. 轮询等待完成，下载生成的图片
6. 返回 `Text2ImageResult`（含图片字节流 + 提供商信息）

### 3.5 安全实现

#### 3.5.1 认证体系

```
SecurityConfig.java
├── 禁用 CSRF（API 无状态）
├── 配置 URL 权限规则
│   ├── /api/auth/** → 公开
│   ├── /api/admin/** → ADMIN 角色
│   ├── /uploads/** → 公开（静态资源）
│   └── 其他 → 需认证
├── 无状态 Session（STATELESS）
└── 注册 JwtAuthenticationFilter
```

#### 3.5.2 JWT 令牌

`JwtTokenProvider.java`:

- **生成**：用户 ID + 角色 + 邮箱 → 签发 24 小时有效令牌
- **验证**：解析 Token → 校验签名 → 提取用户信息
- **密钥**：配置在 `application.yml` 的 `jwt.secret`

`JwtAuthenticationFilter.java`:

- 从请求头提取 `Authorization: Bearer <token>`
- 验证 Token 有效性
- 设置 SecurityContext（用户认证信息）

#### 3.5.3 CORS 配置

允许前端开发服务器（`http://localhost:3000`）跨域访问后端 API。

#### 3.5.4 密码安全

用户密码通过 Spring Security 的 `PasswordEncoder`（BCrypt）加密存储，不存储明文。

### 3.6 ComfyUI API 命令行客户端

#### 3.6.1 概述

`ComfyUI_API/` 是一个独立的 Python CLI 工具，实现了与后端相同的 ComfyUI 交互流程，支持通过命令行直接调用 ComfyUI 生成图片。

#### 3.6.2 技术栈

- Python >=3.14
- requests >=2.34.0
- pytest >=9.0.3
- uv（包管理器）

#### 3.6.3 CLI 使用

```
uv run python main.py [选项] <正向提示词>

参数：
  prompt             正向提示词（必需）
  -n, --negative     负向提示词
  -s, --server       ComfyUI 地址（默认 http://127.0.0.1:8188）
  -o, --output-dir   输出目录（默认 outputs）
  -O, --output-file  直接输出到文件
  -w, --workflow     Workflow 文件（默认 Workflow.json）
  --steps            采样步数（默认 20）
  --cfg              CFG 尺度（默认 8.0）
  --seed             随机种子
  --width/--height   图片尺寸（默认 512x512）
  --timeout          超时秒数（默认 120）
  --poll-interval    轮询间隔（默认 2）
```

#### 3.6.4 输出格式

```
outputs/
└── YYYYMMDD_HHMMSS/
    ├── ComfyUI_00001_.png
    └── prompts.json    # { positive, negative, prompt_id, timestamp }
```
